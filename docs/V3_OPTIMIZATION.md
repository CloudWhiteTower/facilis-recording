# v3 全应用优化与验证

更新：2026-10-08。版本 `3.0.0 / 3000000`，保持 API 24、现有包名和录音目录。录音与转换继续使用系统音频接口，应用保持纯离线，不新增运行时依赖。

## 实现

| 环节 | 变化 | 作用 |
| --- | --- | --- |
| 页签切换 | 开启 HdsTabs 原生内容滑动，继续使用系统动画和既有录音导航保护 | 左右滑动可在录制、资料库和设置之间切换；录制及暂停期间保持当前页 |
| 横竖屏 | 竖屏统一居中纵向布局和底部页签宽度；宽度达到 600 vp 且宽大于高时才分栏 | 平板竖屏不再误用两栏，手机横屏也能使用并排控制区 |
| 短横屏窗口 | 按实际高度预算波形、控制区及底栏空间；播放器缩小图形，资料库和设置改为小标题栏 | 减少按钮被底栏遮挡，极矮窗口仍可纵向滚动；质量面板限制高度并保留滚动 |
| 录音页减字 | 隐藏录音标题栏并释放其空间，保留格式、计时和图标的无障碍名称 | 录音页以波形与图形控制为主，不再显示左上角“录音” |
| 视觉尺度 | 复用系统字体，集中定义字号、行高和字重；工具图标、菜单行、转换/质量选择及主按钮使用共同尺寸 | 同类内容保持一致，计时数字使用等宽特性以减少读数跳动 |
| 连续波形 | 按测量历史、尺寸和分贝范围缓存插值曲线；逐帧仅平移横坐标，渐变按主题和状态复用 | 减少显示同步回调中的数组、曲线和渐变创建，保持原来的振幅和移动轨迹 |
| 边缘光 | 缓存圆角路径；尺寸变化时重建 | 避免每一帧重复提交整条边框的几何命令 |
| 资料库 | 缓存搜索结果和日期分组，隐藏页面首次加载延后至可见时 | 减少无关状态变化带来的过滤、分组和文件读取 |
| 批量文件操作 | 一次读取两个目录，复用事务成功后的列表；操作之间让出主线程 | 大量选择时界面能更新忙碌状态；成功批次不再逐条重新扫描全部录音 |
| 批次与新录音并存 | 索引写入增加版本计数；批次让出线程后检查是否发生其他保存 | 防止批次中的旧快照覆盖期间新保存的录音 |
| PCM 录制 | 仅合并已排队的数据，最大合并块 64 KiB；保留 2 MiB / 64 包背压限制 | 存储繁忙时减少异步写入和 Native 工作项，不为凑块而延迟新音频 |
| WAV 恢复 | 每写入约 5 秒音频更新一次文件头并同步；暂停时也更新 | 异常结束前已完成的前缀能被识别，减少整段 WAV 无法打开的情况 |
| 采集停滞 | PCM 录制连续 5 秒没有收到数据时停止采集并尝试保存已写入内容 | 避免显示计时正常而实际没有继续收到录音样点 |
| 实际采集参数 | 在开始和暂停后重建采集器时读取实际采样率、声道、位深及编码类型 | 参数不一致时拒绝写入新样点并释放资源；继续录音失败时保留此前的合法前缀 |
| 音频转换 | 复用重排缓冲区；相同 PCM 表示直接写入；AAC 完整帧直接提交，最后一帧补静音 | 降低重复分配和复制，保留不满一帧的尾部样点；补齐不超过 1023 样点 |
| 解码调度 | 每轮最多提交、取出各 8 个缓冲；输入使用 1 ms 有界查询，输出非阻塞，没有进展时短暂等待 | 避免满输入队列的零等待查询被映射为参数错误，保留批处理、取消和停滞超时 |
| AAC 编码延迟 | 继续向解码器提交依赖帧，排除标记 DISCARD 的解码输出 | 转换后的 PCM 不再多出编码预热样点，时长与独立解码一致 |
| 转换进度/取消 | 按实际消耗的 PCM 更新进度，进度单调且去重；FLAC 编码等待检查取消 | 减少进度条反复更新和取消等待；只有文件登记成功后显示完成 |
| 播放控制 | 播放/暂停最多等待 8 秒，超时隔离旧实例；录音、播放回调捕获界面异常 | 按钮不会因一次未返回的系统调用持续失效，页面销毁也不会破坏资源清理 |

动画沿用系统导航、Sheet、HDS 按压光感和既有弹簧参数。Canvas 的请求范围仍是 30–60 fps，短交互仍向系统请求最高 120 fps；这些是请求值，不是实测帧率。后台、不可见、暂停和减弱动效条件下的绘制生命周期保持一致。

WAV 中途检查点仅声明已完成、对齐且具备合法 RIFF 大小的前缀，24-bit 奇数样点的末尾补齐仍只在最终结束时写入。异常退出可能失去最后一次检查点之后的内容；此机制不能保证对断电、硬件故障或严重磁盘损坏的恢复。不会把未完成的录音主动加入资料库可操作列表。

## 视觉与采样精度复核

`VisualTheme` 统一各页面和弹层的文本角色，保留系统字体与字体缩放。正文为 16/24 fp、元数据 13/20 fp、注释 12/16 fp、弹层标题 20/28 fp、计时 18/24 fp；斜杠后为行高。播放器大标题按可用空间使用 28/36、32/40 或 22/30 fp，波形刻度保持 10/14 fp。标题和重点内容统一使用 Medium，辅助文字使用 Regular。

工具图标统一 20，页签和次级录音操作图标 24，录音/播放主图标 28。常规选择与工具按钮高 44 vp，文件操作行高 56 vp；录音/播放主按钮直径 72 vp、独立材质底座直径 96 vp。资料库与播放器的保存、转换、分享、重命名及删除行采用相同文字和图标对齐方式。质量下拉框、下拉选项及转换选项的文字统一 16 fp。

音频复核参考 [AudioCapturer 官方接口](https://github.com/openharmony/docs/blob/master/zh-cn/application-dev/reference/apis-audio-kit/arkts-apis-audio-AudioCapturer.md)和 [OpenHarmony 录音机源码](https://github.com/openharmony/applications_sound_recorder/blob/master/feature/recorder/src/main/ets/controller/RecordManager.ets)，关注实际流参数、状态、振幅读取节奏和资源释放。新增的参数核对用于补上潜在的文件头/样点解释不一致，并不表示本轮已在真机观测到该故障。使用的是 API 8 起提供的 `getStreamInfo()`，保持 API 24 兼容。

参照 [Audacity 的位深与抖动说明](https://manual.audacityteam.org/man/dither.html)，本应用避免不必要的降位深、重复有损转换及给无损复制添加噪声。把实际使用的 PCM 表示转换函数抽出为可直接编译的公共头文件，仍由原有转换链路调用；不新增第二套算法。逐一遍历所有 65,536 个 16-bit 和 16,777,216 个 24-bit 取值，经 F32、S32 往返均逐字节相同。另检查正负满幅、半步舍入、非有限值、部分样点、大小溢出、帧/块尾部及缓冲复用。这些结果验证软件表示精度，不能证明麦克风的有效位深、噪声或声学清晰度。

另外，C++ PCM 检查 **5/5**，以 AddressSanitizer、UndefinedBehaviorSanitizer 运行，无越界或未定义行为报告。独立音频校验工具检查 **7/7**，使用 FFmpeg 生成夹具验证样点数、RMS/DC、静音与满幅统计、声道帧时长，以及 AAC 尾部截断和额外延迟样点的检出；相同 PCM 但采样率不同的输出不会被误判为无损往返。FFmpeg 夹具只验证校验工具，不作为本应用编解码器的真机证据。

Debug、Release 和 `entry@ohosTest` 均已构建。最终 Release 已覆盖安装到真实 MatePad Air（API 24），未卸载应用或清理用户录音。最终设备回归 **80/80**：57 项单元、10 项 FLAC、6 项转换、3 项流式/取消、1 项三格式麦克风录制/播放和 3 项界面检查。横竖屏录音控件、质量面板、双向滑动及播放器布局均通过，测试生成的资料库记录已清理，历史记录保全检查通过。

首次真机回归发现输入缓冲查询错误；独立解码进一步发现 AAC 最后一个不完整帧被丢弃，以及解码输出包含预热帧。输入查询改为 1 ms 有界等待，AAC 尾帧补齐，解码时仅排除 DISCARD 输出；保留普通 CODEC_DATA 标记的 PCM 和解码依赖帧。新增 44.1/48 kHz、16/24-bit 输入的 137、1024、1025 样点用例，并以独立 FFmpeg 核对尾部与延迟。

**十分钟 WAV 真机实录通过**：48 kHz / 16 bit / mono，28,831,680 样点，实际音频时长 600.66 秒，57,663,404 字节；录制中检查点文件头可解析，结束后的保存、打开、播放推进和中部拖动通过。此测试后只修改转码与测试，录音核心未变；最终包再次完成三格式短实录回归。

独立 FFmpeg 完整解码 **66 个文件**，其中含最终包三格式麦克风样本、十分钟 WAV、转换输出和已知输入；9 组 WAV/FLAC/24-bit 对比逐样点相同，17 组 AAC 检查确认尾部保留且应用输出与独立解码样点数一致。另有 12 个原生 FLAC 文件与输入 PCM 哈希一致。麦克风样本与十分钟 WAV 均非全零，未出现满幅样点；不同格式是独立实录，不能用振幅高低比较收音质量。未发现应用崩溃日志。公开的参数、信号统计、校验结果和界面截图见 [v3 真机验证记录](../data/v3-validation/README.md)，不包含录音原件。

## 复现

Host 回归命令见[工程测试说明](../HarmonyRecorder/README.md#测试)。真实设备构建与覆盖安装使用 DevEco CLI；需配置自己的签名，且保持原有签名兼容。

```powershell
Set-Location HarmonyRecorder
devecocli build
devecocli build --product default --build-mode release
devecocli build --modules entry@ohosTest
devecocli run --module entry --device <serial>
```

测试包安装后，可使用 SDK 的设备测试命令启用编解码、录制和长录音用例；默认单元测试不访问麦克风：

```text
hdc -t <serial> shell aa test -b com.example.harmonyrecorder -m entry_test -s unittest OpenHarmonyTestRunner -s timeout 900000 -s integration true -s conversion true -s v3 true -s capture true -s soakSeconds 600 -w 1200
```

界面检查可单独启用 `-s layout true`。两项用例在竖屏、横屏中检查录音控件范围、标题移除、质量面板和三页双向滑动，恢复原来的旋转方向，不开始录音。先完成 capture 用例后，可增加 `-s playerLayout true`：将测试麦克风缓存的副本临时登记，检查播放器布局和按钮，结束后只清理本次记录；不选择历史用户录音。三项均已在实体设备执行通过。

实录用例只清理自己生成的资料库记录，并保留缓存副本用于独立解码；已有录音不会被选择。编解码压力夹具以 8192 样点分块生成，PCM 比较以 64 KiB 分块执行。运行长录音前应保证设备已经解锁且电量、剩余空间足够。

将缓存音频复制到本地后，使用独立 FFmpeg 流式解码，检查实际参数、样点数、信号与无损哈希。报告含 RMS、峰值、DC 偏移、非零样点和满幅比例；满幅占比是排查线索，不能单独断定麦克风削波或主观清晰度：

```text
node scripts/verify-audio-streams.cjs <fixture-directory>
```

## 保真与范围

转换不增加重采样、声道混合、DSP 或降噪。WAV/FLAC 无损往返应保持整数 PCM 逐样点相等，AAC 则允许有损编码及编码帧填充；把 AAC 转为 WAV 或 FLAC 不会恢复此前丢失的信息。44.1/48 kHz 单声道、FLAC 输出 16 bit 和 24-bit 输入精度保护的边界保持原状。

目前没有采集 HiSmartPerf 帧时间、系统功耗或扬声器/耳机主观听感，也不声称定量加速倍数。GitHub 发布与 AppGallery 正式审核、发布签名是不同交付步骤。
