## 录制与保存

WAV 使用 AudioCapturer 采集 PCM，保留所选 44.1/48 kHz、16/24 bit、单声道参数；FLAC 采集 16 bit PCM 后交给系统编码器；M4A 由 AVRecorder 编码 AAC-LC 并封装。

录音时分块写文件，避免将长录音全部保留在内存中。PCM 写入处理部分写入、队列上限、完整样点边界和 RIFF 大小限制；保存前等待编码器输出完毕，再同步、关闭文件。暂停时间不计入录音时长。保存后重新读取实际文件头，以实际样点数或容器时长更新资料库。

文件放在 `context.filesDir/recordings/`，最近删除放在其 `recently_deleted/` 子目录。索引只保存文件名；每次运行按当前沙箱重建路径，不保存安装相关绝对路径。生成文件名时同时检查磁盘与尚未打开的录音预约，同一秒保存也不会覆盖前一段。

保存失败时停止采集，保留非空文件；损坏、未完成文件会显示为“文件待检查”，可以备份或手动删除。容器检查不能代替完整解码，也不证明音频信号可听。

## 播放

打开前校验文件确实属于本应用资料库，再从真实文件头取得参数。AVPlayer 使用独立只读文件描述符；原生实例释放结束后才关闭描述符。切换、退出或重新打开会使旧回调失效。

媒体输出在初始化阶段配置为音乐流；应用内相对音量设为 1，系统媒体音量和耳机/扬声器路由仍由系统决定。音频打断、输出设备断开会暂停播放并保留提示。运行中的错误会清除就绪和播放状态，显示具体错误，而不是继续显示正在播放。

拖动以 `seekDone` 为完成依据；连续拖动保留最新目标，旧的进度事件不会拉回滑块。完成后的重播先等待回到开头再播放，快速点击不会叠加多个异步操作。

准备阶段（含创建播放器）最多等待 15 秒，Seek 最多等待 8 秒。超时会显示错误并释放旧实例；Seek 的旧回调没有请求 ID，因此超时后通过“重新打开录音”恢复，避免把迟到回调当作新请求的结果。

## 保存到文件与分享

资料库和播放器的更多菜单提供“保存到文件”。系统 DocumentViewPicker 让用户选择位置，应用使用返回 URI 分块复制原文件；等待同步、关闭成功后才提示完成。原件保留在资料库中。取消选择不创建副本；复制失败清理本次新建的不完整目标。用户选择覆盖已有外部文件时，失败不能保证恢复该外部文件的旧内容。

“分享原始文件”仍调用系统分享面板。WAV 的“导出原始 PCM（无文件头）”仅提取真实 `data` chunk，不包含文件头、RIFF 补齐字节或附加元数据。PCM 需要接收方自行指定采样率、位深和声道，普通播放器不一定能打开；日常保存或播放应使用 WAV、FLAC 或 M4A。

## 应用内转换

更多菜单中的“转换格式”生成新文件，保留原件。处理链路是解封装 → 解码 PCM → 编码/封装；WAV 的 PCM 直接分块读写。转换在原生异步工作中执行，页面提供进度与取消；主动取消或页面销毁会取消任务。只有完整输出、释放编码资源并同步文件之后，才加入资料库；取消或失败不会登记半成品。

| 来源与目标 | 当前行为 |
| --- | --- |
| WAV 16 bit ↔ FLAC 16 bit | 保留采样率和 PCM 样点，无损转换 |
| WAV / FLAC → M4A | AAC-LC 有损编码，可选 128/256 kbps |
| M4A → WAV / FLAC | 解码已压缩音频，不能恢复此前丢失的信息 |
| M4A → M4A | 重新编码，可修改码率；提高码率不恢复音质 |
| WAV 24 bit → M4A | 使用浮点 PCM 输入 AAC 编码器，避免预先截成 16 bit |
| 24 bit → FLAC | 当前实现不支持，明确阻止，不静默降低位深 |

本应用当前转换范围为 44.1/48 kHz、单声道；不做重采样或声道混合。这是当前实现范围，不是 FLAC 格式本身的限制。FLAC 格式支持的参数范围远大于此。[FLAC 规范 RFC 9639](https://www.rfc-editor.org/rfc/rfc9639.html)

AAC 按编码帧处理，文件末尾可能带填充样点。2026-09-27 的模拟器样本中，48,037 样点输入编码后解码为 48,128 样点，44,137 样点输入解码为 45,056 样点。v3 在真机中进一步核对短于一帧、整帧及一帧多一个样点的输入：最后一帧最多补齐 1023 个静音样点，编码预热帧不写入转换结果；17 组独立检查的应用解码样点数均与 FFmpeg 一致。这些 AAC 路径不承诺与未压缩原件逐样点相同。

原生实现参考官方[音频同步解码](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/synchronous-audio-decoding)、[音频同步编码](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/synchronous-audio-encoding)、[解封装](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/audio-video-demuxer)与[AVCodec 格式支持](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/avcodec-support-formats)。纯音频转换使用 AVSource、AVDemuxer、AudioCodec 与 AVMuxer。
